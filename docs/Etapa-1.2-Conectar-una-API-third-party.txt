Continúa trabajando en la rama stage-frontend.

Tendrás que hacer lo siguiente:

implementar la funcionalidad requerida, que verás en detalle más abajo;

Interacción con una API
Ya elegiste qué servicio de API third-party vas a utilizar. Lo primero es abrir su documentación y buscar cómo se autentica, porque de eso depende cómo armas cada petición. Hay servicios que no piden nada: llamas al endpoint y listo. Otros te dan una clave al registrarte y la esperan como parámetro en la dirección de la petición. Otros piden esa misma clave en un encabezado, casi siempre Authorization. Y unos pocos usan esquemas más elaborados, con tokens que caducan y hay que renovar.

Si tu servicio te da una clave, guárdala en una variable de entorno con el prefijo VITE_, por ejemplo VITE_API_KEY: Vite solo expone al navegador las variables que empiezan así. En el repositorio queda el .env.example, no el .env. Eso saca la clave del repositorio, pero no la esconde: en la aplicación desplegada cualquiera puede leerla, así que usa la clave de un servicio gratuito y no la de una cuenta que te importe.

Añade cierta funcionalidad a tu página web utilizando la API para proporcionar datos. Configura las solicitudes y sus endpoints. 

Implementar las solicitudes
Crea un archivo en la carpeta /utils para trabajar con el servicio third-party y ponle un nombre que diga de qué servicio se trata, por ejemplo weatherApi.ts o pokeApi.ts. Si más adelante haces la parte full stack, tu propia API vivirá en otro archivo, y así no se confunden.

Este archivo contendrá las solicitudes al servicio third-party. Escribe estas solicitudes utilizando el método fetch(). Aprovecha TypeScript para describir con tipos o interfaces la forma de los datos que esperas recibir de la API. Puedes utilizar funciones regulares o clases para estructurar tu código.

Visualizar los datos
Guarda la respuesta en una variable de estado con useState: el componente se vuelve a renderizar solo con los datos nuevos. Si quieres conservarlos entre visitas, escríbelos también en localStorage.

Hasta que se reciban los datos se puede mostrar un preloader. Si la búsqueda no devuelve resultados, en lugar del preloader aparece el mensaje "No se encontró nada".

Si algo falla al pedir los datos, muestra este mensaje: "Algo salió mal con la solicitud. Puede ser un problema de conexión o del servidor. Inténtalo de nuevo más tarde."

Una vez recibidos los datos, el preloader debería desaparecer y deberían aparecer los elementos adecuados.

Diseña cuidadosamente cómo se mostrarán los datos recibidos. Si tu API devuelve una lista muy larga de elementos (como tarjetas o artículos), te recomendamos no mostrarlos todos a la vez para no saturar la pantalla. Puedes implementar una forma de mostrarlos gradualmente: por ejemplo, mostrando los primeros resultados y agregando un botón "Mostrar más", o utilizando una paginación sencilla.

Si el usuario ha cerrado la pestaña y luego ha vuelto a la página, puedes leer los datos de localStorage al montar el componente App. Tendrás que configurar la interacción con localStorage y la variable de estado en el orden correcto.
